# mailer-service

Отдельный микросервис отправки писем: подключается к почтовому провайдеру (SMTP-relay ESP),
принимает письма по HTTP, держит очередь с рейт-лимитом и ретраями, принимает вебхуки провайдера
и пробрасывает статусы доставки обратно в основное приложение.

Обслуживает и **авторассылку** (основное приложение шлёт письма триггеров по одному),
и **массовую рассылку** (`/v1/send/batch`).

## Зачем отдельно
- ESP-интеграция и прогрев домена изолированы от бизнес-логики.
- Единая точка рейт-лимита и ретраев для всех рассылок.
- Своя очередь (SQLite) — сервис самодостаточен, без внешней БД.

## Запуск
```bash
python3.11 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env        # заполнить SMTP_* и CALLBACK_URL
.venv/bin/uvicorn app.main:app --port 8080
```
Пустой `SMTP_HOST` → dev-режим: письма только логируются (для локали/тестов).

## API
| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | статус + счётчики очереди |
| POST | `/v1/send` | одно письмо `{to, subject, html, from_email?, from_name?, meta?}` → `{id}` |
| POST | `/v1/send/batch` | массовая рассылка `{messages:[...]}` |
| GET | `/v1/messages/{id}` | статус письма (queued/sent/failed, событие) |
| POST | `/v1/esp/webhook` | событие от провайдера `{message_id, event}` |

`meta` возвращается без изменений в обратном вызове — основное приложение кладёт туда свой
`log_id`/идентификаторы, чтобы связать событие доставки с письмом в своей БД.

## Поток
```
Основное приложение ──POST /v1/send {..,meta}──▶ mailer-service (очередь)
                                                   │ воркер: SMTP + рейт-лимит + ретраи
                                                   ├─ событие "sent" ─────────────────┐
Провайдер (ESP) ──вебхук {message_id,event}──▶ /v1/esp/webhook ─ маппинг по message_id ┤
                                                                                       ▼
                                          POST CALLBACK_URL {..meta, event}  ──▶ основное приложение /esp/webhook
```

## Настройки (.env)
`SMTP_*` — провайдер. `RATE_PER_MIN` — антифлуд/прогрев. `MAX_ATTEMPTS`/`RETRY_BASE_SEC` — ретраи.
`CALLBACK_URL` — эндпоинт событий основного приложения. `API_TOKEN` — защита API.
